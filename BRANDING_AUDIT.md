## `neko` identifiers intentionally retained

These are compatibility or implementation identifiers, not public branding.
They must not be globally replaced without a coordinated core migration.

- `NekoGui` C++ namespace and `NekoGui_*` source filenames: internal ABI/source
  organization used throughout the GUI.
- `github.com/matsuridayo/libneko`: pinned Go dependency and its public import
  path. Renaming it requires maintaining a separate Go module fork.
- `nekobox_core` executable and the `nekobox` core launch argument: the GUI/core
  process contract. Both sides must be changed together.
- `nekoray_auth`, `enable_nekoray_connections`, and
  `nekoray_connections_json`: gRPC/protobuf compatibility fields. Renaming them
  is a breaking protocol and stored-data change.
- `ToNekorayShareLink` and “Neko Links”: an existing import/export format.
  Keeping it allows h. to read links generated by compatible clients.
- `:/neko` resource prefix and `res/neko.qrc`: internal compiled resource paths;
  they are not visible to users.
- historical updater migration names such as `nekoray.zip`: retained only so a
  user can recover or migrate an old installation. The h. UI no longer invokes
  the upstream release updater.
- VPN rule entries containing old process names: retained for compatibility
  with older cores and side-by-side migration.

## UI upgrade

The final theme layer is `res/h-premium.css`. It is applied after the selected
Qt theme, providing a consistent dark navy surface, cyan/blue focus treatment,
rounded controls, quieter borders, improved table hierarchy, modern tabs,
menus, inputs, scrollbars, status bar, and high-contrast connection controls.

## Assets

- `res/public/h-logo.png`: transparent high-resolution source logo.
- `res/h.ico`: Windows multi-resolution icon (16 through 256 pixels).

## Remaining engineering work

Visual Studio 2022 Build Tools is installed, but CMake, Ninja, Qt and `qmake`
are not exposed in PATH and the pinned source dependencies have not yet been
initialized. A Windows build therefore still requires the documented Qt 6.7.2
toolchain and the pinned `QHotkey`/`libneko` sources before compilation.
